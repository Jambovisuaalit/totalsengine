# Evidence Collector v2 — independent-verifier contract (offline prototype)

**Scope:** Draft PR #3 only. No provider integration, no external WORM storage,
no real timestamps, no actual bookmaker receipts, no production publishing.

`verification_v2.py` checks **Ed25519 signatures** against an explicit
role/issuer/subject public-key registry. Signed claim domains are prefixed
`TOTALS_ENGINE_V2_ED25519_ENVELOPE\\0`; signatures are over canonical JSON
including schema v2, role, key ID and claims. Keys are verified only, never
generated by the application. Test keys are ephemeral and generated in
`tests_nba_totals/test_verification_v2.py` (synthetic only).
The registry is NOT loaded from user-submitted claims. Real trust roots
must be pinned in a separate, reviewed, protected verifier service.

Six separate required signers:
1. Independent timestamp witness must sign the exact local receipt digest
   and original source payload digest at/before T−60, with issuer time and
   anchor ID. This is **custom Ed25519 witness proof**, **not RFC3161**.
   A real provider-independent timestamp should use RFC3161 or an
   equivalently independently audited service. Signed timestamp alone
   is not a WORM/immutable object-storage guarantee.
2. Licensed feed origin must sign original payload digest, quote ID,
   source ID and provider publication time.
3. Rights registry must confirm source ID, bookmaker, territory,
   commercial betting signals use, redistribution, retention, contract,
   grant validity and independent issuer enrollment.
4. Bookmaker acceptance verifier must sign **accepted** price, exact
   bookmaker/quote, accepted stake (EUR), accepted market price, bookmaker-confirmed stake limit,
   acceptance ID and time.
   This component never places or requests a wager. A price displayed
   on a feed is NOT an accepted bet.
5. Independent model validator must sign OOS/calibration/no-lookahead
   results bound to the paper assessment/model version.
6. Publisher authorization signer must approve policy/territory.
   This is merely a contract: no publisher or delivery channel exists.

Important: Tests can generate valid synthetic Ed25519 signatures with
independently named signers, establishing that the verifier rejects
tampering, wrong roles, expired/revoked grants, wrong odds or region.
**Synthetic signatures cannot validate real rights, bookmaker execution
or independent timestamp authority.** No live roots configured.
`assess_bundle` always returns `verdict=NO_GO` and
`publication_allowed=false` even if all *synthetic* checks are true.
`cryptographic_dry_run_eligible` is a test-only diagnostic, never
production release authority.

Provider, license, timestamp and bookmaker acceptance integration
requires actual third-party authorization and production-specific
security review. Previously exposed NBA credential must remain revoked.
